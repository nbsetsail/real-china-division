# 中国行政区划数据集 · 活更新版

> 省地县乡四级民政口径区划码 + 乡镇全量 + **1980-2026 变更事件库（5,195 条）** + 别名映射词典，
> 附一个自包含的 Python 解析引擎。零强制依赖。

**这不是又一份冻结的 JSON。** 它带着一条持续更新的生产线：官方渠道变了，我们的获取方式跟着变了。

---

## 一、为什么 2024 年之后，区划数据没人维护了

| 时间 | 事件 |
|---|---|
| 2024-10 | 国家统计局：统计用区划代码和城乡划分代码转为「工作中使用的内部资料」，不再对外公开。2023 版成为最后一期，原发布目录随后整体下架 |
| 2025-09-01 | 民政部令第 79 号《行政区划代码管理办法》施行：每年 1 月经**国家地名信息库**发布上年末省地县乡四级行政区划代码 |
| 2026 起 | 民政部官网「行政区划代码」栏目下线，统一指向国家地名信息库 |

后果：主流免费数据集（xiangyuecn / modood / tonyc726 等）全部冻结在 2020-2023 基线——
不是维护者懈怠，是**「等官方发整表」的模式死了**。

## 二、我们怎么维护：事件驱动，不是被动等表

| 信息流 | 渠道 | 角色 |
|---|---|---|
| 底库 | 国家地名信息库行政区划接口（每年 1 月年度版 + 年内日更新） | 权威基线 |
| 事件流 | 国务院 / 民政部 / 省民政厅区划变更批复公告（带文号） | 增量与溯源 |
| 地名流 | 地名信息库地名搜索接口（村级实体、历史沿革） | 扩容与别名原料 |
| 哨兵 | 地图 API 行政区划 | 变更敏感信号 |

数据随版本发布（tag + 校验和），每一条变更可追溯到事件。**本仓库会持续更新**——这是它与静态快照的本质区别。

## 三、数据内容

| 文件 | 规模 | 说明 |
|---|---|---|
| `data/divisions_v1.json` | 33 省 / 341 地级 / 2847 县级 | 民政口径，官方 12 位码，年度版 2025-12-31 |
| `data/townships_v1.json` | 2,847 县级 / 38,749 乡镇街道 | 五级化，含区县归属 |
| `data/historical_changes_v1.json` | **5,195 条变更事件（1980-2026）** | 撤县设区 152 / 撤县设市 390 / 撤地设市 122 / 更名 879 / 同名改码 2221 / 划转 / 撤销 / 新设；1980-2020 由官方代码簿逐年差分，2021+ 手工策展（带文号） |
| `data/*.csv` | 同上平行格式 | 通用消费（divisions / townships / change_events） |
| `aliases.json` | 手工策展别名词典 | 历史名 / 古称 / 地标 / 简称 / 歧义 / 特殊口径，每条带来源 |

### 数据字典（核心字段）

- **divisions**：`{省: {code, cities: {市: {code, counties: {县: 12位码}}}}}`；CSV 版 `code,name,level,parent_code`
- **townships**：`{县级12位码: {county: 县名, townships: {乡镇名: 12位码}}}`
- **change_events**：每条含 `year / type / level / old(code,name,path) / new(code,name,path) / doc_no / source`；`doc_no` 为增量回填字段

## 四、解析引擎（engine.py）

自包含单文件，零强制依赖（可选安装 `pypinyin` 启用拼音纠错）：

```python
from engine import resolve, resolve_by_code

resolve("襄樊市樊城区")        # 历史名 → {'status':'resolve','result':'湖北省-襄阳市-樊城区',...}
resolve("通州区")              # 同名歧义 → 输出候选集，不猜测
resolve("雄安新区容城县")      # 非民政建制 → 正确归属保定市
resolve("苏州工业园区")        # 非正式区划 → 诚实标注特殊口径
resolve("深镇")                # 错字 → 拼音纠错 → 广东省-深圳市
resolve_by_code("510124")     # 历史码回溯 → 郫都区，注：2016年撤县设区
```

引擎特性：别名/历史名解析（事件库自动生成 489 条映射）、同名歧义输出候选集、
开发区/新区/兵团等特殊口径诚实标注、拼音错字纠错、编码直查与历史码回溯、
不留存架构（纯函数无状态）。

## 五、口径诚实声明（Don't trust, verify）

1. **双口径差异**：统计口径的村级「城乡分类代码」是统计局专属，自 2024-10 起无现行公开渠道。
   本数据集**不提供、不编造**；村级实体以民政地名口径另行发布（Roadmap）。
2. **早期噪声**：1984 年前全国代码多次重编，事件库中该时期存在代码串扰噪声，重要结论请以民政批复原文为准。
3. **非正式建制**：开发区/新区/园区在民政口径中不是正式建制，引擎按「特殊口径」标注而非硬归。

## 六、与其他数据集的关系

静态快照类项目（xiangyuecn、modood、tonyc726 等）是优秀的公共品，**低时效需求直接用它们完全没问题**。
本仓库的差异化：持续更新的事件驱动管线、变更事件库、别名/历史名映射、解析引擎与历史码回溯。
我们主张的是「持续维护」这一层，感谢前人铺路。
